O problema secundário é que o Service utiliza selector `app=ecommerce-apps` (plural) enquanto os pods possuem label `app=ecommerce-app` (singular), resultando em zero endpoints mesmo se o pod conseguisse iniciar.

**Trigger Inicial**: Deploy ou atualização do Deployment com imagem Docker inválida/inacessível

**Efeito Cascata**:
1. Kubernetes tenta fazer pull da imagem `fabricioveronez/ake-shop:v1`

4. Deployment atinge timeout após 10 minutos (ProgressDeadlineExceeded)
5. Zero réplicas disponíveis para servir tráfego
6. Service não consegue criar endpoints devido a selector incorreto
7. LoadBalancer externo criado mas sem backends


### Correlação Causal

- **Causa (K8s)**: Imagem Docker `fabricioveronez/ake-shop:v1` não existe ou inacessível

- **Evidência**: Erro explícito "pull access denied, repository does not exist or may require authorization" (197+ ocorrências)

#### Causa-Efeito 2: Pod Não Inicia → Deployment Sem Réplicas

- **Causa (K8s)**: Pod em ImagePullBackOff nunca fica Ready
- **Efeito (K8s)**: Deployment com 0 réplicas disponíveis (esperado: 1)
- **Efeito (Prometheus)**: `kube_deployment_status_replicas_available{deployment="app"} = 0`
- **Evidência**: Deployment condition MinimumReplicasUnavailable

#### Causa-Efeito 3: Selector Mismatch → Service Sem Endpoints

- **Causa (K8s)**: Service selector `app=ecommerce-apps` não match com pod label `app=ecommerce-app`
- **Efeito (K8s)**: Service endpoints: `<none>` (zero backends)
- **Efeito (Prometheus)**: LoadBalancer criado mas sem roteamento possível
- **Evidência**: `kubectl get endpoints app` mostra `<none>`

#### Causa-Efeito 4: Zero Réplicas + Zero Endpoints → Aplicação Indisponível

- **Causa (K8s + Prometheus)**: Deployment sem réplicas disponíveis E Service sem endpoints
- **Efeito (Negócio)**: Aplicação 100% inacessível para usuários
- **Efeito (Prometheus)**: SLA disponibilidade = 0%, nenhum target da app nos targets Prometheus
- **Evidência**: `curl http://146.190.198.5` resultaria em timeout/connection refused

### Correlação Confirmatória

#### Validação 1: PostgreSQL Funcional (Controle Negativo)

- **Hipótese**: Problema NÃO é de infraestrutura geral ou conectividade de rede
- **Evidência K8s**: Pod postgres em estado Running, 1/1 ready, sem eventos de erro
- **Evidência Prometheus**: `pg_up = 1`, conexões ativas = 2, commits = 23,669, rollbacks = 0

#### Validação 2: Imagem Docker como Causa Raiz

- **Hipótese**: Causa raiz é imagem Docker inválida/inacessível
- **Evidência K8s**: Erro "pull access denied" em 197+ tentativas, nenhuma outra mensagem de erro no pod

- **Conclusão**: ✅ Confirmado - Imagem Docker é o bloqueador primário

#### Validação 3: Selector Mismatch como Bloqueador Secundário

- **Hipótese**: Mesmo se pod iniciasse, tráfego não seria roteado devido a selector incorreto
